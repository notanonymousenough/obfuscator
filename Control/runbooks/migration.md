# Принятие рабочих backend и откат

Текущий статус: **не выполнено**, ожидается подтверждение переключения рабочего трафика. Копии backend прошли локальные проверки. Изменения будут вызывать короткие переподключения; UUID/секреты/домены сохраняются.

1. На каждом узле нужна одна свободная root tmux-панель `0:0.0`, открытая оператором через `sudo su`. Не создавать NOPASSWD.
2. Проверить `python3 Control/orchestrator.py status`, сохранить текущий приватный реестр. Не менять клиентов параллельно с миграцией.
3. Для импортированных копий на master выполнить `python3 Subscriptions/scripts/root-tmux.py de1 Control/scripts/adopt-master-bindings.sh`: upstream не объединяет одинаковые имена с разных узлов автоматически. Скрипт сначала сохраняет приватный SQLite backup, затем требует совпадения UUID/subId/secret и добавляет только отсутствующие привязки. Повтор безопасен. Проверить точное совпадение клиентов старого процесса и копий; скрипт откажет при расхождении. Если старый CLI менялся после импорта, сначала повторно сверить/обновить копии, а не обходить защиту.
4. После явного разрешения оператора: `python3 Control/orchestrator.py stage`, затем `python3 Control/orchestrator.py cutover`.
5. Порядок DE2 → AZ1 → DE1. На каждом узле nginx переводится на Xray панели 8545, общий MTProto — с Telemt на Xray 8446. Внутри границы отката проверяются HTTPS204 через публичный TLS/VLESS/XHTTP и MTProto HMAC. Затем старые сервисы останавливаются/отключаются.
6. После всех узлов включается `obfuscator-panel-delivery.service`. Локальный `control.json` получает `mode=active`. Старый node-agent запрещает reconcile/portal, чтобы два реестра не перезаписывали друг друга.
7. Проверить публичную подписку, две VPN-схемы, приватный DE2, оба MTProto backend и stats панели. В Happ обновить прежнюю подписку; ссылки не меняются.

При ошибке coordinator пытается вернуть каждый затронутый узел, включая узел с неясным результатом. Резервные файлы: `/var/lib/obfuscator-control/backups/cutover/`; прежние приложения и БД — в timestamp-папках `/var/lib/obfuscator-control/backups/` и `/usr/local/x-ui.precontrol-*`.

Ручной откат **в рамках миграции, до последующих правок клиентов**:

```sh
python3 Control/orchestrator.py rollback
```

После изменения клиентов в UI старые JSON-конфиги становятся устаревшими. Перед поздним откатом экспортировать/сверить текущие идентичности на узлах: простой возврат старого snapshot отменит более поздние выдачи/отзывы. После отката сверить рабочие клиенты и лишь затем вернуть локальный `mode=bootstrap`.

Откат backend не откатывает обновление 3x-ui: прежние legacy inbounds и БД сохранены. Для отката самого приложения остановить x-ui, вернуть соответствующий `x-ui.precontrol-*`, приватную БД и старый unit из одного timestamp-backup; не смешивать БД разных версий и WAL. Это отдельная восстановительная операция.
