# Направление развития Obfuscator

Актуализировано 28.10.2026 по текущему решению владельца. Отдельные AI, Realtime и Payments профили отменены. Публичные продукты — VPN-подписка `obfuscator.funsociety.dev` и общий Telegram proxy `mtp.funsociety.dev`. DE2 выдаётся отдельно, в основной подписке скрыт.

## Сейчас

Happ получает DE1/AZ1 через персональную обновляемую подписку. У клиентов собственные UUID и MTProto-секреты. MTProto backend DE1/AZ1 балансируются за единым DE1 ingress. AZ1 умеет прямой вход с проверяемым DDNS и резерв через сохранённый reverse SSH. Старые x-ui клиенты и ключи сохраняются. Подробности и фактические проверки — [Subscriptions](../Subscriptions/README.md).

## Следующие этапы

1. **Приёмка из РФ.** Минимум мобильная и фиксированная сеть: импорт Happ, реальный HTTPS/UDP через VPN, переподключение после потери входа, Telegram сообщения/медиа и звонки через VPN. Проверять отдельно туннель и доступность Telegram, Claude, Grok, ChatGPT, Discord, Google Pay. HTTP403 или неподдерживаемая карта не являются доказательством поломки VPN.
2. **Наблюдение маршрутов.** Состояние хранить для `источник → вход → выход`, а не один зелёный индикатор хоста. TCP/TLS, аутентифицированный XHTTP probe, ожидаемый egress, DNS, UDP. Пробы без РФ показывать как «из РФ не проверено». DOWN после нескольких ошибок, возврат после нескольких успешных проб, удержание маршрута против постоянных переключений.
3. **Убрать единый отказ DE1.** Сейчас домены подписки/MTProto и AZ1 relay зависят от DE1. Для следующего уровня нужен независимый публичный ingress у другого провайдера/ASN, реплика delivery registry, проверяемое DNS-переключение. Два backend за одним публичным IP не переживут блокировку этого IP. Активные TCP не мигрируют бесшовно.
4. **UI поверх существующей модели клиентов.** Список клиентов, создать/отозвать/ротация, скрытый DE2 как явное право, состояние применения, серверы/маршруты, сертификаты, DDNS, резервные копии. Раздельные роли operator/read-only, MFA, журнал действий без секретов. Админка доступна через защищённый management-доступ; публично только delivery. Постоянный удалённый root API сейчас не вводится: оператор явно выбрал root tmux.
5. **Связка хостов и реалистичная среда.** Независимая смена входа при фиксированном exit, затем изолированный браузер/приложение на pipe с постоянным профилем и явно выбранным немецким выходом. Pipe физически в Азербайджане, поэтому его сеть сама по себе не немецкая. Дополнительные hop не меняют репутацию exit IP или fingerprint браузера. Не обещать обход ограничений сервисов по одному DC-IP.
6. **Воспроизводимость.** Единый inventory, pinned версии, автоматический preflight/backup/validate/rollback; восстановление нового узла на стенде и проверка отзыва клиента. Переход от tmux к постоянному ограниченному management agent — только отдельным решением владельца.

## Существующие решения и выбор

| Решение | Применение | Ограничения для проекта |
|---|---|---|
| [Xray](https://github.com/XTLS/Xray-core), [routing / observatory](https://xtls.github.io/en/config/routing.html) | Сохраняем VLESS/XHTTP как проверенный владельцем транспорт | Серверный balancer не помогает, когда сам вход заблокирован у клиента |
| [Happ](https://github.com/HappDev/happ_su) | Основной мобильный клиент, стандартная URI subscription | Режим авто-выбора и UDP необходимо проверить на используемой версии телефона |
| [Telemt](https://github.com/telemt/telemt) | Отдельный multi-user FakeTLS MTProto, не трогает legacy x-ui | Работоспособность Telegram и звонков нельзя вывести из открытого TCP443; звонки проверять через VPN |
| [HAProxy health checks](https://www.haproxy.com/documentation/haproxy-configuration-tutorials/reliability/health-checks/) | SNI ingress, TCP pool, прозрачный TLS passthrough | TCP check не заменяет end-to-end авторизацию |
| [Remnawave](https://github.com/remnawave/panel), [Marzban](https://github.com/Gozargah/Marzban) | Кандидаты для зрелого управления пользователями/узлами | Миграцию делать отдельным пилотом с проверкой импорта существующих UUID; текущие x-ui базы не заменять |
| [Mihomo](https://github.com/MetaCubeX/mihomo), [sing-box](https://github.com/SagerNet/sing-box) | Клиентские health checks / policy routing в будущем | Формат и совместимость с Happ проверять отдельно; текущая подписка — простой список VLESS |
| [Headscale](https://github.com/juanfont/headscale) / [NetBird](https://github.com/netbirdio/netbird) | Возможная закрытая management-сеть | Не считать WireGuard-only overlay заменой anti-DPI входа из РФ |

Германия допустима для выхода. Google Wallet/NFC дополнительно зависит от устройства, карты/банка и поддерживаемого сценария; удалённый Linux-браузер не заменяет телефон для NFC. Политику доступа сервисов проверять при конкретной приёмке, без автоматической ротации exit на любой отказ приложения.
